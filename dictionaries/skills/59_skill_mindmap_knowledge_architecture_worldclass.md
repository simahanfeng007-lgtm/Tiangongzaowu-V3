# 世界顶尖级脑图与知识结构交付 Skill

## 适用范围
用于思维导图、脑图、知识结构图、概念层级、主题拆解，以及需要 Mermaid mindmap 与 OPML 双格式交付的任务。

## 输入契约
- 中心主题、目标受众和使用场景。
- 希望回答的核心问题与边界。
- 已有素材、指定层级或必须保留的节点。
- 是否需要 OPML；未明确时，正式交付默认同时生成 OPML。

## 工具流程
1. 先用 `file.mkdir` 建立项目目录；若有素材，用 `file.read` 读取。
2. 用 `file.write` 落地一份可维护的缩进源大纲：首个非空行是唯一根节点，其余节点用每级 2 个空格缩进。
3. 调用 `mindmap.create`，`target` 为 `.md`，`args.source` 指向源大纲，正式交付时设置 `opml=true`。不要把长大纲再次内联复制到 `args.content`。
4. 用 `file.read` 复核 Mermaid 代码块以 `mindmap` 开始、根节点只出现一次、层级缩进有效；用 `file.read` 复核 OPML 是完整 XML 且节点非空。
5. 若结构不平衡、重复或孤立，修订源大纲后重新生成。最终用 `file.list` 确认只保留源大纲、脑图 Markdown、OPML 和交付说明。

## 结构原则
- 根节点只承载主题，不重复成为一级分支。
- 一级分支通常保持 4 至 8 个；同层节点采用同一抽象粒度。
- 每个关键分支至少展开两层，并用动作、指标、证据或风险等具体节点落地。
- 节点使用短语，不把段落硬塞进图中；必要解释放在源大纲或交付说明。
- Mermaid Markdown 是可阅读、可版本管理的主交付；OPML 用于后续导入脑图软件。

## 验收
- `mindmap.create` 的返回证据显示 `content_mode=source_text`，源文件位于当前工作区。
- Mermaid 可解析，只有一个根节点，不含空标签。
- OPML 可作为 XML 解析，标题和节点层级与 Mermaid 一致。
- 源大纲被保留，后续修改只需编辑源文件并重新生成。
