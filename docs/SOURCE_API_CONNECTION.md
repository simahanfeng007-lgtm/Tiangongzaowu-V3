# 源码版首次配置与 API 连接排查

源码不包含任何人的模型密钥。首次启动后，在「设置」中选择服务、协议、地址和模型，输入自己的密钥并保存；等待后端就绪，再点击连接测试。连接测试会发送一次可能计费的短文本请求，不自动重试，也不代表工具调用或任务完成验收已经通过。

## 源码配置位置

Windows 通过 `scripts/setup-source.ps1` 安装依赖，再运行 `scripts/start-source.ps1`。默认配置放在仓库父目录的 `data` 下，模型配置在 `data/home/.tiangong`，桌面凭据库在源码版独立的用户数据目录。指定 `-ProfileRoot` 或 `TIANGONG_SOURCE_PROFILE_ROOT` 会更换整套配置目录。

因此，同一台机器的安装版已经设置密钥，也不代表新拉取的源码版已经设置。不要把另一台机器的加密凭据文件当作可移植密钥；请在当前机器重新保存自己的密钥。不要把密钥提交到 GitHub、日志或问题截图中。

## 地址与协议

地址、协议、模型及账号套餐必须相匹配。OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 使用各自的请求格式。自定义服务以服务方提供的信息为准。

Anthropic Messages 支持根地址、以 `/v1` 结尾的地址和完整 `/v1/messages` 地址；不会重复拼接 `/v1`。其他协议也识别已经包含对应操作路径的地址。自定义路径前缀和查询参数会保留。

## 需要代理的网络

默认模型请求直连。需要使用已经配置的 HTTP/HTTPS 代理时，在启动应用的终端中设置 `TIANGONG_HTTP_TRUST_ENV=1`，并按本机代理软件提供的地址配置 `HTTPS_PROXY` / `HTTP_PROXY`，再重启源码版。Windows PowerShell 示例：

```powershell
$env:TIANGONG_HTTP_TRUST_ENV = "1"
# HTTPS_PROXY / HTTP_PROXY 使用自己的代理地址，不要照抄其他机器的端口。
.\scripts\start-source.ps1
```

显式启用后，模型执行与连接测试使用相同的后端网络配置；本地网关的 `localhost`、`127.0.0.1`、`::1` 保持直连。此开关只影响应用进程，不修改系统代理。不需要代理时关闭该开关并重启。

## 根据测试结果定位

| 结果 | 含义与下一步 |
| --- | --- |
| 密钥缺失 | 在当前源码配置中保存密钥；检查是否切换了配置目录或服务。 |
| 后端尚未就绪 | 检查启动日志、依赖与本地网关启动状态。此时尚未向模型服务发请求。 |
| HTTP 401 | 服务端拒绝当前凭据；核对账号、密钥和服务地址。 |
| HTTP 403 | 服务端拒绝访问；核对权限和服务方限制。 |
| HTTP 404 | 核对地址、模型名称及账号套餐对应的接口。 |
| HTTP 429 | 频率限制或额度不足；依据服务端账号状态处理。 |
| 超时／网络传输失败 | 检查当前网络、DNS、代理和服务状态；不自动重复可能计费的请求。 |
| 收到无效响应 | 返回内容不是所选协议的有效结果，例如网关返回了 HTML 页面。 |
| 连接成功 | 本次鉴权与该模型的短文本请求成功；流式输出、工具与真实任务需另验。 |

反馈问题时，请提供操作系统、启动方式、源码提交号、服务/协议/模型和上述错误码。不要提供密钥。
