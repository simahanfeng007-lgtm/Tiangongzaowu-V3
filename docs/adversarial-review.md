# 对抗智能体决定任务完成

2026-09-26：普通字典执行循环默认由隔离上下文的对抗智能体判断任务是否完成。执行模型只能提出候选结果；裁判确认后才交付。原来“只提建议、系统决定完成”的行为保留为显式对照模式，不再是默认值。

## 执行与裁决

1. 执行模型按原任务、字典组合和现有工具权限工作。候选终答暂存；进度保留工具动作，不提前流出候选终答或其摘要。
2. 裁判读取原任务、运行中用户引导、实际工具观察、历史裁决和准备交付的完整答复。模型没有工具，不从文件名推断文件内容，也不能授予权限。图片、音频等缺少实际感知证据时必须由裁判考虑覆盖缺口。
3. 裁判明确返回 `complete`、`continue` 或 `blocked`，附理由；继续检查时提供原要求原文、证据引用、具体检查/修复与可观察的失败条件。无反例不再自动等同于完成。
4. `continue` 经原续答通道回到执行模型；执行模型检查、修复或提出有证据的反驳，然后再次提交候选。只有裁判能批准。反馈在 Chat Completions、Responses、Anthropic 的原生工具历史之外显式保留，不伪造工具结果。
5. `complete` 才提交该次已审查的最终答复和附件。判断绑定运行、原任务、用户引导、全部可用观察、候选答复和附件列表的摘要；变化后必须复核。重启不复用历史批准。复核期间收到用户新要求也须再次执行和复核。
6. `blocked` 或裁判不可用时保存已完成工作、原始观察和裁决，返回未完成说明，不作为最终成果交付。网关继续使用既有 `FAILED` 请求终态与 `incomplete` 执行链状态表达未完成；这不等于证明已有文件内容错误。

默认流程不调用旧 Life completion gate 和 regenerative completion proof 来重判任务完成。工具调用的授权、结构验证、真实回执、取消和执行期限仍执行；Gateway/P19 保留运输、执行状态和既有证据登记，不把裁判意见伪造成工具事实或独立内容证明。运行中不再因系统算出“待办数为零”显示完成度 100%；完成状态的来源明确记录为 `adversarial_agent`。

历史的只读重复后交付、学习回执直接收尾等快捷分支也需要裁判。未批准附件保留在检查点，但不通过响应附件和网关产物捕获出口提交。

## 协议与运行限制

`TIANGONG_ADVERSARIAL_REVIEW`：

| 值 | 用途 |
| --- | --- |
| `judge`（默认） | 对抗智能体拥有任务完成裁决权 |
| `off` | 显式旧流程对照，不调用裁判 |
| `shadow` | 显式旧流程对照，记录建议但不反馈 |
| `advisory` | 显式旧流程对照，反馈建议但完成权仍归旧流程 |

未识别值按 `judge` 处理，避免拼写错误静默关闭复核。部署时已有的显式对照设置须改为 `judge` 或移除；本次修改源码默认值，没有改动用户常驻服务或线上环境。

- 裁判协议 `tiangong.adversarial-completion.v1`。系统只核对格式、字段一致性、引用与用户原文来源，不做语义打分。
- 每次调度最多 6 次裁决调用；失败也计数。单次最长 30 秒，受父任务期限与取消约束；剩余不足 40 秒不发起调用并保持未完成。
- 证据包最多最近 12 条观察、32,000 字符观察摘录；摘要绑定所有当前可用观察。输入最多 64,000 字符，完整候选答复最多 12,000 字符。省略、截断明确标记，超出完整候选上限时不能批准。
- `complete` 必须同时提供空的待处理疑点与覆盖缺口。不存在“异常时放行”“次数耗尽自动通过”或“迟到响应补批准”。
- 裁决写入现有 `run_state.adversarial_completion`，保留失败原始记录；对外耗时使用整数毫秒，符合网关签名 JSON 不允许浮点数的协议。
- 当前裁判和执行者可共用同一模型配置，只隔离上下文，不代表模型错误相互独立。完成判断仍可能误判，不能用接线测试宣称所有门类质量问题已解决。

## 验证边界

测试覆盖真实调度循环中的拒绝后再次提交、确认后交付、受阻与协议失败不交付、旧完成门不被调用、候选回复不提前展示、变化与用户新引导使旧批准失效、迟到结果、取消、预算、网关记录格式、附件出口及三种模型协议的反馈送达。

验证面升级为 1.38；使用官方冻结更新和生成镜像同步流程。Store schema、字典条目和工具权限未变。本地证据与实跑结果见工作区 `acceptance/adversarial-completion-2026-09-26/实施报告.md`；未进行云端同步、安装版升级、Windows 原生或全门类正式验收。

本候选最终专项 392 项通过、139 个子测试通过。真实文件任务经历 `continue → complete` 后由网关完成交付，另行字节/清单核验通过；真实代码任务经历 `continue → blocked`，因 Linux 执行隔离不可用保持未完成，没有成功 CompletionDecision。裁判的批准本身不能替代独立内容核验。本地首候选的浮点耗时字段曾导致网关传输失败，已修复为整数毫秒并保留原始失败。
