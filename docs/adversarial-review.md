# 基于现有执行事实的对抗复核

本地第一版，2026-09-26。此功能复用当前模型客户端、原字典组合执行循环、运行记录和完成判定。它产生可检验的建议，不创建另一套事实账本、权限入口或质量分数。

## 运行流程

1. 普通任务实际调用过工具，且主模型准备给出终答时，从已有观察构造有界证据包。纯聊天、模型错误和关闭状态不调用裁判。
2. 裁判使用当前配置的模型，在隔离上下文中读取任务、用户后续引导、候选终答和真实工具观察。它没有工具、原生执行历史、音频输入或隐式 Skill 注入，也不会自行读取磁盘。
3. 每条疑点包含用户要求的原文片段、候选主张、已有观察引用、具体检查建议，以及可观察的错误条件。协议检查保证引用存在、原文确实出现在用户输入中；这不证明裁判理解正确。
4. 在建议模式中，将复核意见作为明确标注的不可信模型建议送回主模型。续答在当前消息中显式保留这份反馈，避免原生工具历史替换时丢失；不伪造 function call/result。
5. 主模型判断建议是否相关，必要的检查仍由 `omni_body composition` 登记和执行，沿原 Gateway/Effect/观察链回传。可拒绝无关建议，或说明无法取得的证据。原 P19 和 Completion 判定不读取裁判的状态作为 PASS/FAIL。

`counterexample` 仍是模型声称发现了矛盾，必须结合真实检查理解。`check_needed` 表示待检查的假设；`no_counterexample` 只表示当前证据中没有找到反例；`inconclusive` 表示无法判断。没有综合评分，也不从原文关键词制造硬性义务。

## 启用与边界

由启动进程的 `TIANGONG_ADVERSARIAL_REVIEW` 设置模式：

| 值 | 行为 |
| --- | --- |
| `off`（默认） | 不增加裁判调用，保持原任务流程 |
| `shadow` | 记录复核建议，不回传以改变本轮执行 |
| `advisory` | 记录并回传有效建议，主模型按原要求决定后续行动 |

未识别的模式按 off 处理。第一版不默认推广到所有任务；局部样本不能证明总体收益。没有新增安装配置、密钥、后台服务或常驻裁判进程。

- 每次调度执行最多 2 次尝试；失败和非法结果也消耗次数。同一观察与用户要求不重复采样，候选回复仅改措辞不会触发重复复核。
- 单次子调用上限 20 秒，受父调用及执行期限约束；任务剩余不足 30 秒时跳过，并记录原因。输出上限 3072 tokens。
- 最多选取最近 12 条观察、32,000 字符观察摘录，输入总上限 48,000 字符。所有省略或截断显式标记，引用绑定未截断的原观察摘要。观察引用标识历史回执，不等于当前文件字节哈希。
- 新工具观察使旧建议标记过期；第二次预算用完后出现新证据，明确标记未复核。状态与最多两份报告保存在现有 `run_state.adversarial_review` 中，不进入成功事实法定数。重启历史建议不作为新产物的验收依据。
- 超时、服务不可用、非法 JSON、引用错误均记为未完成复核；不制造工具失败，也不产生内容通过记录。取消/超时后的迟到响应不会更新建议。
- 裁判与生成者当前可能是同一个配置模型，仅上下文隔离；这不等于统计独立。真实性最终仍需要来源、实际执行、独立算法或人工评价。
- 本版只消费已获得的文字和结构化观察。不能仅靠文件名审查图片、音频、视频或专业软件渲染；缺少感知证据时应记录覆盖缺口。

## 关键实现

- `app/backend/tiangong-backend/v3/adversarial_review.py`：证据包、严格协议、调用预算、建议记录。
- `app/backend/tiangong-backend/v3/zongdiaodu.py`：在任务收尾前发起复核并回到原执行循环。
- `app/backend/tiangong-backend/v3/gutong/gutong_ceng.py`：显式投递非工具复核反馈，保留来源标记。
- `app/backend/tiangong-backend/v3/simple_chain/kernel.py`：已有进度投影展示复核状态，并标记旧报告过期。

复用的辅助调用在 DeepSeek Chat Completions 下会为可非思考的模型关闭思考，保留有限 JSON 输出空间。本次补上实际配置使用的 `deepseek-chat` 旧别名；主任务推理及 `deepseek-reasoner` 不受此分支影响。开关语义依据 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)，旧别名本次实测服务端返回 `deepseek-flash`，不保证别名长期可用。

验证面显式升为 1.37，新增模块和反馈入口进入原冻结清单；Store schema 不变。Source Authority 通过原配置登记新增模块，生成镜像使用官方脚本同步。

## 验证与后续准入

自动测试覆盖非法/伪造引用、额外要求、重复 JSON 字段、超时与取消、迟到调用、证据变化与过期、预算限制、真实文件读取及 Chat/Responses/Anthropic 反馈保留。已有字典、世界上下文、执行状态及完成门回归一起执行。

最终专项回归为 295 passed、25 subtests passed、5 条既有字段命名警告；Source Authority、提交镜像、字典构建和冻结检查通过。本次未重复全库 Python/Node，也没有 Windows 原生或安装版验证。

最终候选的 4 个真实裁判探针分别为正确数字、错误数字、正确短文本与缺少画面证据，均达到预期判定方向，且输入文件不变。Word 真实任务 COMPLETED，独立产物核验通过。反馈接线修复后的 Excel 任务则实际补做 `file.hash`、`file.list`，原生回执与 Gateway 中两条成功叶子观察对应，最终产物核验通过；两者的具体源码身份在外层证据中分别绑定，不能混成一次实验。

Excel 单对照样本中，关闭复核为 41.466 秒，建议模式为 98.236 秒；主任务调用由 7 次变成 11 次。并行实验的运行波动、生成路径和其他辅助调用共同影响该数值，不能把差额视为普遍固定开销或质量收益。现阶段仍默认 off。

本地实测证据在项目外层 `acceptance/adversarial-review-2026-09-26/`。既保留中间失败，也记录最终源码身份：早期测试入口未注入凭据、辅助调用思考额度耗尽，以及续答丢失反馈的记录，不计作最终成功。准确结果与使用边界见该目录的 `实施报告.md`。

推广前应以固定任务/模型/预算做 QA0（原事实反馈）、QA1（独立复核）、QA2（对抗检查）的分类配对实验；分别量化错误放行、误拦、未覆盖项、修复收益、成本和时延。本次是可运行的第一版及局部链路验证，不是全门类质量有效性结论。
