**原子能力精简原则与首批变更（2026-09-27）**

用户已授权从第一性原理删除或修改不必要的原子单位。因此，全量方案的目标是覆盖有价值的实际能力；现有条目数量、名称、粒度和历史划分都可以调整，不要求机械实现当前每个占位名称。本文件补充本体能力实施方案，首批只处理源码已能证明冗余的入口。

**判断依据**

原子单位应当提供独立、可观察的状态读取或状态改变，并有明确的输入、结果、对象范围及失败行为。这里的原子性是执行与恢复的边界，不是代码行数，也不要求每次只能调用一个底层 API。

| 情况 | 处理方式 | 必须核对的事实 |
|---|---|---|
| 真实且独立的观察／操作 | 保留并补契约 | 没有该单位会失去什么能力；结果如何观察 |
| 完全等价的多入口 | 合并或删除；确有兼容需求时保留显式别名 | 输入输出、权限、副作用、对象范围和恢复语义都等价 |
| 可以可靠组合的业务目标 | 移交现有模型生成的 Tool／Skill | 组合能覆盖原承诺；不会丢失底层事务原子性或必要一致性 |
| 名字声称质检，实际没有相应观察或判断 | 删除虚假的独立能力，复用真实读工具及原裁判 | 原入口究竟返回什么；替代路径能否读到真实内容 |
| 一个动作混合独立读写或不相关副作用 | 在已有协议中拆分或明确模式 | 权限、失败、重试和部分成功是否能够分别核对 |
| 没有后端的占位声明 | 先确认需求和可行路线 | 尚未实现本身不是删除依据；不删除需求来制造覆盖率 |
| 历史兼容或退役定义 | 先核对实际引用、恢复和迁移 | 不能把旧计划自动解释为新能力或改写旧证据 |

不能因为通用 Python／Shell 理论上能做一件事，就删除全部专业工具。专用接口可能保留更精确的权限、更可靠的事务、结构化结果或更低执行成本。反过来，按行业起不同名字也不能证明存在不同的原子能力。

**首批删除的 12 项**

| 删除的动作 | 原实际行为 |
|---|---|
| `rubric.evaluate` | 返回文件大小或输入文本字节数，内容评价为未评估 |
| `qc.research.evidence_check` | 同上；没有核验来源与论断 |
| `qc.writing.ai_tone_check` | 同上；没有判断语言风格 |
| `qc.novel.chapter_check` | 同上；没有判断叙事质量 |
| `qc.sheet.analysis_report_check` | 同上；没有验证计算与结论 |
| `qc.meeting.minutes_check` | 同上；没有对照会议记录 |
| `qc.sales.script_check` | 同上；没有判断话术效果 |
| `qc.course.plan_check` | 同上；没有判断教学设计 |
| `qc.kb.ingestion_check` | 同上；没有核实实际导入 |
| `qc.voice_authorized.delivery_check` | 同上；没有观察音频内容或验证授权 |
| `qc.seo.people_first_check` | 同上；没有判断页面质量 |
| `qc.content.calendar_check` | 同上；没有验证排期约束 |

这些函数都调用同一个元数据辅助函数，返回 `score=null`、`acceptance=null`。删除前已核对：没有其他字典别名依赖这 12 个名称，没有应用目录引用，也没有独立参数／结果 schema。其名称会出现在模型的已实现原子列表中，却不能提供名称承诺的独立观察，因此删除。

已有 `file.hash` 可以观察文件字节身份和大小，`file.read` 可以读取文本，`preview.generate` 可以提供实际内容摘录。领域内容还应调用相应的真实读取工具，并由现有对抗智能体判断。已有输入文本本身无需绕行一个工具，再把原文长度误当成额外质量证据。没有新增替代系统或新动作。

`qc.docx.delivery_check` 还包含显式长文档清单的结构检查分支，本批保留；其他执行实际格式、结构或进程检查的接口也没有因名称含“质检”而一并删除。它们返回的局部检查结果不取得任务完成权。

同步删除源注册表、分发分支和 12 个包装函数，更新相关产物模板及当前工具说明。专业应用说明不再要求调用已退役的 `skill.route`／`skill.get`；骨架生成器不再提示“运行质检直到通过”即可交付。
