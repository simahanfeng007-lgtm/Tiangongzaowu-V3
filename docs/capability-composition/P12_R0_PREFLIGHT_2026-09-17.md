## Implemented diagnostic

`scripts/audit-p12-static-skill-retirement.py` is a standard-library-only,
read-only developer command. It is never imported into Gateway or Runtime.

It checks an independently supplied exact HEAD and ancestor baseline, rejects
tracked worktree/index changes, reads native Git blobs without importing product
modules, verifies blob hashes, and binds the observer's own bytes to the commit.
It inventories five lexical-reference categories, with paths, line numbers,
matched tokens and file hashes. It does not output full source lines or secrets.
References in tests and developer scripts are labeled separately. Authoritative
source ownership and generated mirrors are not reclassified.

The R0 change check accepts only additions of this batch's four exact files.
Any product edit, deletion, extra runtime, policy change or other modification
returns a failed R0 scope result. No compiler, permission, release, Source
Authority, Golden baseline or generated mirror changes are permitted in R0.

Symlinks/submodules are not followed. Binary, oversized and non-UTF-8 inputs are
explicitly listed as unscanned. Text and total input budgets are bounded; truncated
match lists are marked. Missing required runtime roots are an error, not evidence
of zero use. Native Git scanning does not hydrate LFS assets or read live state.

The report always retains:

```text
evidence_mode = STATIC_GIT_INVENTORY
p11_exit_proven = false
p12_authorized = false
retirement_authorized = false
production_zero_usage_proven = false
```

A lexical inventory is **not** a complete call graph, live telemetry, capability
parity, independent review, or a production retirement certificate. Even zero
matches does not prove zero production use. The command has no approval option.

## Reproducible commands and evidence

trusted GitHub record, not from an untrusted report:

```text
python -m unittest discover -s tests -p test_p12_retirement_preflight.py -v
python scripts/audit-p12-static-skill-retirement.py --expected-head <P12-candidate-40-character-SHA> --baseline-head bf29542b3048c8d1806add8063b0db7c72be055b
```

The CLI writes JSON to stdout, not to source or production storage. Exit 0 means
valid static inventory and R0-only changes; 1 means invalid/incomplete inspection;
2 means the candidate exceeds the R0-only change scope. None approves retirement.

Pre-publication local validation: **24 tests passed, no failures or skips**, on
Linux/Python 3.13.5 using synthetic, temporary Git repositories. Tests cover
commit/observer identity, dirty trees, protected-component deletion, unauthorized
scope changes, native-object tampering, truncation, symlinks, binary/encoding/size
limits, token-only output, deterministic hashes and non-authorization invariants.
These are diagnostic-contract tests, not tests of the full product or real models.

The read-only Ubuntu/Windows workflow uses Python 3.12 and the existing repository's
action major versions. It runs the same tests and then inventories the actual
exact-commit repository. It preserves original logs, inventory bytes and identity
hashes for 90 days. Its contents permission is read-only; it cannot push or deploy.
Remote results are pending at document creation and must be recorded separately
against the returned commit. They cannot inherit P11's green CI results.

The local executor could read GitHub through the connector but could not directly
