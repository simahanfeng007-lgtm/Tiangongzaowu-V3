# P16-A 150 轮长链验证方案冻结（v1.0）

编制：2026-09-20。性质：方案冻结文档——定义「轮」、负载、观测与停止条件；执行依赖 R02/R03 资源（真实模型与原生环境），资源未备时本方案保持冻结、不降级执行。

## 一、「轮」的定义（冻结）

一轮 = **一次真实主链交互**：用户消息经现有入口（duihua_qiaojie → Zongdiaodu.huanxing 用户分支）进入，经上下文组装、规划/登记（受控组合回合或旧链之一——按当时生效模式）、工具执行、Effect/Fact、P19 验证与 Completion 判定，至交付回执可观测为止。

- 一轮必须产生连续的 request/run/generation 身份与 ledger 记录；纯函数调用、单测重跑、批量 pytest 均不计数。
- 中断/取消/重试分别计数并标注（不冒充连续成功轮）。

## 二、任务负载（冻结）

150 轮按以下配比构造，输入文本各不相同（不同 input hash 与 goal fingerprint，禁止复制同 prompt 凑数）：

| 类别 | 轮数 | 说明 |
|---|---|---|
| 普通任务（A0 读/验类） | 60 | 单步/少量步骤、真实可验证产物 |
| 依赖任务（DAG≥2 步） | 40 | 上游输出为下游输入 |
| 需验证/修复任务 | 25 | 触发 P19 verifier 与（受控）修复流 |
| 反例任务 | 15 | 权限拒绝/能力缺失/用户取消 |
| 边界事件注入 | 10 | 分布于 C 节中断矩阵的注入点 |

## 三、边界事件矩阵（冻结，配合 P16-C/D）

在以下注入点各至少触发一次：规划前、模型响应中、登记事务中、ticket 后 effect 前、副作用开始后、事实写入前后、验证中、交付前后。

## 四、观测字段（冻结）

每轮记录：request_id/run_id/generation、活动路径（受控组合/旧链）、模型身份（精确 provider/model/revision）、Plan/Source/Manifest/registry 哈希、Ticket/Grant id、Effect/Fact/P19/Completion 结论、token 开销、时延、错误与修复记录。连续性判据：150 轮的 ledger 无未解释断口；采集器断开即停止计数并如实报告。

## 五、停止条件与预算

- 任一出现即停并如实报告：False Completion>0、未授权动作、身份漂移、来源漂移误用、资源/句柄泄漏超阈。
- 模型/工具预算按矩阵合同预付；不因长链无限追加。
- 失败轮保留原文，不删除不重编号。

## 六、范围边界

- 本方案不替代 P11/R1G 的 200 任务矩阵（不同合同）。
- 原生 Windows/AppContainer 边界属 P16-EXIT；Linux 受控执行先行时明确标注非原生。
- 资源未备（R02/R03）时本方案保持冻结；不得以夹具冒充轮次。
