## Explicit Verification Plane 1.6 addendum

The existing `runtime_security.path_identity` metadata observer now opens the
complete DOS/UNC path using NtCreateFile, FILE_OPEN, FILE_READ_ATTRIBUTES,
OBJ_CASE_INSENSITIVE | OBJ_DONT_REPARSE, with no following fallback. The
opened and normalized NT names must bind the complete input suffix and the
same native volume/location prefix on that same handle. Failures, pending
status, invalid handle/namespace, buffer overflow and cleanup failures reject.
Only API bindings/types are cached; no path or handle observation is cached.

`verify_relative_path` still checks exact relative names and native volume/
location, plus link/reparse attributes. The complete-path no-reparse open
covers ancestors above the selected root, replacing—not deleting—the former
ancestor safety property. `resolve_existing_path` expands proven 8.3 spelling
and independently reobserves the expanded path before returning it. This
preserves the existing canonical workspace hash semantics. POSIX retains
strict pathlib resolution. No second authority, permission expansion, global
pathlib change, TEMP rewrite or ACL/registry alteration is introduced.

A returned pathname is a point-in-time observation, not a retained file handle,
future-import guarantee or immutable Run/source proof. Existing byte inventory,
source hash, selected-installation, principal, Policy/Ticket/Grant and P19
checks remain necessary and unchanged. UNC grammar has protocol fixtures;
real remote-share acceptance is not asserted by local-disk AppContainer tests.

The old root-redirect fixture mocked the now-removed root-open mechanism. Its
rejecting propagation remains, and independent FFI flag/status plus real
ancestor-junction tests verify the replacement no-follow boundary. Two host
fixtures now compute the canonical expected path before injecting DOS-query
failure, rather than demanding the original short spelling. The source-read
no-candidate-import fixture preloads the additional trusted UTF-16-LE codec.
No success/failure oracle, Golden corpus or covered authority entry is removed.
The official UPDATE_FREEZE generator updates only the existing helper digest,
followed by an ordinary freeze check with that environment flag absent.
