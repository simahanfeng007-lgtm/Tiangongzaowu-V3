# 用户认可的动态组合经验

字典继续提供原子能力，由 LLM 根据当前需求生成 Tool 和 Skill。记住的是用户认可的一次做法及其证据，不向字典添加固定业务 Skill，也不重放旧执行权限。

2026-09-25 增加的自动失败观察沿同一记忆权威保存，使用独立 DATA 类型，不要求先获认可，也不冒充认可经验。其跨任务召回、稳定认知与主动探究边界见 [学习闭环修复说明](learning-closures-repair.md)。本文的用户认可规则继续适用。

## 实现

1. 普通任务通过组合登记、逐步执行和完成检查。仅 `COMPLETED`、存在真实成功组合、没有结果不明步骤的任务可保存为认可经验。
2. 用户点击“认可并记住”，或明确表达“这个做法对，请记住，以后复用”。前端通过桌面认证接口提交具体任务标识。自然语言由当前模型分类，不可调用工具，最长等待 60 秒；部分认可或含糊回应不会认可整个组合。
3. 从 Gateway 执行账本取得组合代码、动作、依赖、参数、逐步结果和失败尝试。记录绑定任务、运行代次、结果版本、工作区、生命身份、字典动作定义和真实反馈。注册成功、模型声明或进程退出码不能代替任务完成和用户认可。
4. 经现有 `MemoryCoordinator` 写入 L1 来源事件和 L3 活跃经验头，复用既有加密载荷和 SQLite。第一次明确认可即可参考，不要求先成功五次。
5. 新任务先用词项与中文双字片段筛选经验，再将有限数量的具体实例作为 DATA 交给 LLM 判断。模型读取新输入、替换路径与参数、生成新组合，并用 `composition.experience_refs` 标明采用的经验。新组合重新登记、重新取得本次执行授权。
6. 复用记录绑定新任务的 Request/Run/Generation、程序哈希与真实叶子步骤。只有相关步骤实际全部成功且任务完成，才记复用成功。声明引用而未执行不增加成功记录；后来其他步骤修好了任务，也不会抹掉被引用组合的失败。
7. 撤销、所用动作定义变化、复用失败后停止推荐该版本。失败证据保留，后续正确结果须重新获认可。状态查询或下次召回会补记中断期间遗漏的终态。旧认可重试不能覆盖新撤销。

## 入口与源码

- `POST /api/v1/gateway/composition-feedback`：`inspect`、`accept`、`withdraw`、`interpret`，仅桌面认证入口。
- `src/total_gateway/composition_experience.py`：反馈、执行证据、召回、引用与结果回写。
- `src/life_service/composition_memory.py`：现有记忆权威下的持久化和活跃版本。
- `src/capability_dictionary/composition.py`：组合协议中的可选经验来源。
- 前端 `actions.mjs`、`state.mjs`、`conversation-panel.mjs`：自然反馈、按钮与跨会话状态。

## 联调修正

- 原组合登记只返回 `argument_schema_invalid`，丢失了具体问题。现回传失败叶子、参数诊断、期望字段与工作区；拒绝的组合仍不执行。
- 原沙箱写入证据只有相对路径，无法对应绝对输出路径。执行器现报告实际提交工作区，证据转换据此解析路径并拒绝越界，不把“读取到文件”当作写入证据。
- 原会话序列化丢弃消息元数据，切换或重启后失去任务关联。现保留经过字段校验的必要标识，异步认可仍绑定原会话。
- 新经验曾被旧记忆兼容层重复投影，重启后同时从原生记忆与旧投影进入上下文，触发标识冲突。现在由组合经验专用入口读取，旧投影会清理，权威记录保留；通用记忆路径也不会绕过撤销、工作区和版本筛选。
- 任务在后台会话完成时，也把认可入口绑定到原会话的结果，避免切换会话后丢失按钮。

## 边界

- 这是保存、召回、适配与反馈闭环，不保证模型以后不会犯同类错误。
- 检索目前不是向量语义检索，跨语言、近义词或弱词面关联可能漏召回；模型仍须判断是否适用。
- 单次最多 3 条、合计 42,000 字符；过大的完整程序暂不注入，避免截断代码。长组合压缩、通用参数抽象未实现。
- 按生命身份和工作区隔离，未实现跨用户或跨工作区共享。
- 失败会记录和停用，但自动归因、自动修复复测、自动推广新版本尚未实现。纯失败任务不会进入“用户认可的成功经验”。
- 仅认可部分结果时不会自动拆分局部经验；自然反馈指向当前会话最近的具体任务。
- 动作定义变化可触发停用；底层执行器实现变更后的全面兼容性验证仍是独立事项。
- 历史代码和结果只是参考；新任务中的内容、外部资源、权限和质量重新验证。

## 验证要求

确定性测试覆盖真实 SQLite 重开、版本绑定、撤销、重复反馈、工作区隔离、动作变更、部分认可、实际步骤成败、未执行引用、不同代次隔离、分类原话绑定和中断恢复。前端覆盖按钮、自然反馈、会话切换和重开。

真实验收链：普通前端消息生成并执行组合 → 模拟明确用户认可 → 重启进程 → 新会话及不同输入、不提示复用 → 核对实际经验引用和新产物 → 核对持久化复用结果。具体验收数据与失败尝试保存在本次测试记录中，不以单元测试代替这项结论。

本次结果见 [2026-09-24 验证报告](composition-experience-verification-2026-09-24.md)。
