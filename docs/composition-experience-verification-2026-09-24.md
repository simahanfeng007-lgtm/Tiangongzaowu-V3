## 联调中发现并修复的问题

1. 第一轮使用了不属于当前 QA 工作区的目标，组合被拒绝，但模型只能看到笼统的参数错误，反复尝试后超时。现在把失败叶子、具体字段诊断和当前工作区传回模型；验收脚本也改为读取实际配置。
2. 第二轮已生成正确文件，却因沙箱仅报告相对路径，无法满足绝对路径的写入证据而未完成。执行器现在报告真实提交工作区，证据层据此解析且检查路径包含关系。
3. 第三轮仍遇到上述证据问题，因为修正最初落在生成副本。随后修正在权威源码 `src/omni_body_skill`，重新同步全部副本；第四轮首次任务完成。失败记录保留。
4. 自然认可首次已写入记忆，但前端把回执当作隐藏模板，用户看不到。现在使用可见的“做法记忆”回执；会话序列化保留必要任务标识，切换/重启不丢失认可按钮。
5. 首轮跨会话复用在进入模型前失败：旧兼容投影重复注入同一条原生经验，触发 `context item identity collision`。现在通用记忆排除受管组合经验，由专用召回执行版本、工作区、撤销和失败筛选；清理旧投影而保留权威记录。失败现场数据库副本可成功编译授权，后续真实复用完成。
6. 代码复核发现后台会话完成时可能丢失认可关联，已修正并通过新增前端测试。

中途一批测试有两个夹具错误（重复副作用目标、无效失败枚举），修正夹具后通过；原失败 XML 也保留，未计入最终失败数。

另外观察到通用 HTTP 服务的既有问题：未认证 POST 的请求体可能留在复用连接上，紧随的请求收到 501。重新连接后的版本校验返回正确的 409。这次没有修改通用 HTTP 传输层；该现象保留在 `controls.json`，独立复测在 `version-check.json`。

## 当前成长能力的边界

- 已实现：首次明确认可即可记住；跨进程、跨会话参考；适配新输入；真实复用结果记账；撤销和失败后停止推荐该版本。
- 检索使用词项与中文双字片段，可能漏掉弱词面相似任务；不是通用语义检索。最多注入 3 条、合计 42,000 字符，超大的完整程序暂不注入。
- 仅同一生命身份、同一工作区；没有跨用户或跨工作区共享。
- 失败会留证并停止推荐，**没有实现自动归因、自动修复复测、自动推广新版本**。本次失败停用主要通过真实账本的确定性用例验证，没有宣称完成真实模型的自主修复闭环。
- 部分认可不会自动拆分局部经验；动作定义漂移会阻止复用，执行器实现变更后的兼容性仍需另行验证。
- 不能承诺“做错一次以后永远不再犯”。本次真实任务仅覆盖代码执行、CSV 汇总及简报，未据此重新宣称视频、图片、PPT 等所有任务类型通过。
