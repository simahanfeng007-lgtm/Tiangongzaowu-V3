# 执行修复与缓存优化实测（2026-09-26）

> 历史实验记录；当前协议、后续修复与最终候选验收见 [v3 实施记录](v3-reliability-implementation.md)。以下数字只属于文中列出的旧候选。

## 结论

发现执行问题后先修复，再实现并验证缓存改造。最终本机隔离 Gateway 的代码修复、文件整理、图片处理、Word 生成四个真实模型任务均 COMPLETED，均由对抗智能体裁决 complete 后产生一个 CompletionDecision，独立产物检查全部通过。不是全部 791 项能力已验收，也不是安装版、生产或 Windows 验收。

当前不能宣称 99%。最终四任务主调用的合计加权命中率为 71.19%，单任务 58.12%–76.70%，单次请求最高 95.05%。包含首轮，分母是服务端实际 input tokens；辅助与裁判调用另列在 comparison.json。较早增量候选单次最高 96.28%，不能代替最终候选的成绩。

## 修复的执行问题

- 普通字典 Python/Shell 在 Linux 原来因缺少 OS 隔离实现而不能实际执行。现在由 bubblewrap 挂载系统只读运行时及私有工作区副本，隔离进程、网络和环境，施加进程/内存/输出/时间限制；失败、超时及取消不提交工作区修改。沙箱不可用时仍拒绝执行。
- 脚本内部写死的工作区绝对路径，不能仅靠 argv 替换处理。现将同一私有副本映射到工作区原路径，父目录和宿主相邻文件仍不可见；成功后经既有 broker 合并。真实隔离测试验证原路径读写及失败不合并。
- system.health 的 allow_python/allow_shell 是当前调用授权，而非全局能力状态；增加明确说明。
- zip.extract 补齐实际修改/未变化文件的写入证据，避免已解压却被认定没有产出。
- image.resize 修复保持比例时只能缩小、不能放大的问题；256×256 图片字节像素复核符合参考结果。
- 已签名的 composition.workspace-python.v1 仍是原 Windows AppContainer 配置，不将旧签名自动扩展到 Linux。

发现并保留的中间失败包括：用户命名空间中 bwrap 所有者 UID 映射、旧外层测试容器禁止嵌套命名空间、启动状态挂载顺序错误，以及脚本内绝对路径未映射。未修改内核策略或采用无隔离执行兜底。

## 缓存改造

主任务按 run 独立维护已经成功的完整出站消息前缀，新原生调用/结果、当前反馈和世界状态追加到末尾。三种传输协议共用机制，保留原生 call/result 与私有续答绑定。失败请求不提交，输出格式修复从已成功历史重新构建；过时并发结果不能覆盖新历史。辅助/裁判模型调用不继承主任务缓存上下文。

动态世界状态采用无损分块更新：首次完整视图，随后仅替换变化块；提供基准/新视图 SHA-256、最终块数和替换文本，发送前逐字还原验证。新 packet/handle/时效信息完整保留，不做模型摘要，不冻结旧身份。增量不足 15% 估算节省时使用全文；身份、工具或原生历史改变时重建；超过配置窗口 75% 的估算预算时以当前有效完整组和最新全文重建。预算是历史保留策略，不能保证单个巨大原生结果不会超窗。

首次仅追加全文的候选，代码命中率 55.46%，输入 80,549、未命中 35,877；发现多数收益来自重复旧状态，随后加入无损增量。最终代码为 58.12%，输入 76,196、未命中 31,908。相较执行修复后的旧布局（3 次调用、68,188 输入、35,932 未命中、47.30%），最终也是 3 次调用，未命中下降 11.20%，但总输入增加 11.74%。不能把命中率改善等同于同比例成本下降。

## 最终真实模型结果

配置 deepseek-chat，服务端报告 deepseek-flash；模型不可变 revision 未验证。输入与失败原文、SSE 可见输出、任务记录、SQLite、产物和各候选源码身份均保留。

| 任务 | 主调用 | 总输入 tokens | 未命中 tokens | 全任务命中率 | 单次最高 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 代码修复 | 3 | 76,196 | 31,908 | 58.12% | 69.61% |
| 文件整理 | 7 | 379,345 | 88,401 | 76.70% | 95.05% |
| 图片处理 | 4 | 145,192 | 49,064 | 66.21% | 77.32% |
| Word生成 | 4 | 110,738 | 35,602 | 67.85% | 81.87% |

代码的 4 个隐藏用例通过，真实 python.run 退出 0、linux-bubblewrap、network=denied、result.json 经合并产生。文件字节/层级/manifest 检查通过；图片 256×256，像素 MAE=0、最大通道差=0；Word 必需内容与原始输入保留检查通过。最终文件任务裁判为 continue→complete，其余一次 complete。只读 SQLite 审计前后 DB/WAL 哈希不变，最终四运行全部正常停机。

14 个之前尝试一并归档，未覆盖失败。各任务的工具选择、验证轮数、服务端缓存预热会变化，本次是非随机小样本，不能从文件任务的命中率上升推断总成本下降。文件任务仍有重复补证，较早候选裁判还曾提出不必要的桌面核验要求；执行方未因此访问桌面。这是后续减少无效质检循环的明确优化点。

测试驱动采用独立进程内 profile 路径和真实产品工具隔离。旧外层 bwrap 在此主机禁止嵌套 namespace，故后续 Gateway 不再套该外层容器；Python/Shell 工具仍使用本次真实 OS 沙箱。没有更改用户常驻配置、桌面服务或代理。
