# 源码 API 连接修复记录

用户报告另一台机器从 GitHub 拉取源码后 API 无法连接，但没有系统、启动方式或报错。以远端 main `4afbb75187ab95ed806eebb46dd59f4185e57a16` 建立独立工作树复现，再并入 PR #114 的本体候选；不能据本次复现断言对方机器的唯一原因。

## 已确认并修复

1. 桌面连接测试单独读取凭据库，遗漏实际执行支持的环境变量与旧 provider 名称映射，可能误报密钥缺失。现通过原 Gateway → 后端客户端，使用当前保存配置、原凭据读取器和实际执行协议。
2. Anthropic 地址带 `/v1` 或完整 `/v1/messages` 时，实际请求重复拼接。三类协议改用同一地址拼接函数，保留前缀与查询参数，避免重复后缀。
3. 桌面启动无条件清空代理变量，导致后端显式 `TIANGONG_HTTP_TRUST_ENV=1` 无效。默认直连不变；显式启用时继承已有代理并让本地控制通道直连。
4. Responses 连接探针原输出上限为 1，低于官方最小值 16，修正为 16。依据 [OpenAI Responses 官方参考](https://developers.openai.com/api/reference/java/resources/beta/subresources/responses/methods/create)，没有据此声称已连接真实 OpenAI 账号。
5. Gateway 在未读取 POST 请求体前拒绝鉴权，却保留 HTTP 连接，下一次请求被解析为 `{}POST` 并返回 501。拒绝连接现明确关闭，客户端重新建立连接；认证、CORS 和请求大小约束保留。

连接探针沿既有 DNS/IP 绑定、TLS、账号作用域、调用生命周期和成本记录。只发一次有界请求，不跟随重定向、不自动重试、不返回原始密钥或厂商错误正文。401、403、404、429、超时、无效/过大响应分别报告；短文本成功不宣称流式、工具、内容质量或任务完成通过。
