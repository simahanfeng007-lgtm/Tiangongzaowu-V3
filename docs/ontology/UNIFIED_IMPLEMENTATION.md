# 天工造物 v3 本体能力统一实施方案

本文件是当前实施主线。用户于 2026-09-27 确认按实际能力、故障及交付覆盖重定验收，并要求所有应用保留接入目标、环境位置通过现有 MCP 发现。历史阶段文档保留原证据，不再以固定任务数、观察数、轮次数或字典模式对照作为本路线的退出条件；这不把任何旧验收改写为通过。

## 目标与权威

用户目标 → 原 World 观察 → 模型动态生成 Tool/Skill → 原 Gateway 授权、执行与事实账本 → 世界和进度反馈 → 唯一对抗裁判 → 当前版本交付。

程序校验显式参数、权限、身份、版本与实际字节；对抗裁判判断业务目标和内容。裁判返回 continue 时，修复必须关联新动作和新观察；建议送达不等于执行。环境变量 off/shadow/advisory 不再绕过普通任务裁判。历史建议记录仍可读取。

复用现有调度器、World、执行账本、MemoryCoordinator、恢复和模型缓存。UI/run_state 是进度投影，不签发完成决定；关键执行证据持久化失败不能当成功。辅助摘要失败可以降级。用户改要求、产物变化、取消及恢复使旧批准失效。

## 一条工作清单

| 工作 | 落点与退出证据 |
|---|---|
| 原子整理 | 从权威字典生成全部动作、显式别名、生命周期、参数契约、代码引用及应用关联；逐项保留、合并、拆分、动态组合或退役。缺账号不是删除需求的理由。 |
| 真实观察 | 校正静态网页抓取、真实渲染、脚本生成和远程完成的范围；明确分页/截断、对象版本、实际账号和来源。 |
| 本地闭环 | 普通用户入口由真实模型读取输入、计算、生成报告、回读、修复并取得裁判批准；保留错误及修复版本。 |
| 浏览器闭环 | 真实渲染、单次交互、分页/下载、回读和裁判。独立页面动作不承诺跨调用保留会话。 |
| 全门类 MCP 接入 | 所有应用从同一字典投影连接需求；用户配置保存服务、环境、账号标签和应用关联。模型发现→连接取实际契约→调用→目标回读。云端/原生应用尚无环境时记录具体缺项。 |
| 恢复及对抗验收 | 按适用的失败类型复验未知结果、部分成功、重复副作用、并发变化、重启、取消、迟到结果、提示注入及错误/过期批准。 |
| 集成及成本 | 精确候选局部/全库检查、真实任务、必需 CI、目标安装环境和回退；随后按批通过 PR 同步 main。缓存只在质量与事实及时性保持的条件下优化实际成本和延迟。 |

旧 P11/P12–P17 数量与模式切换工作包由本表的真实覆盖要求取代；来源发布、对象权限、签名、数据迁移、并发恢复、目标平台及交付证据仍按实际适用范围保留。旧 W0/W1 对应原子整理；W2/W3 对应观察和闭环；W4 对应应用接入；W5/W6 对应恢复、学习和裁判；W7 对应集成。旧 World/学习接线已存在，进入回归而非重复建设。

## 接口与接入

具体参数的动态组合协议、Gateway 授权和完成协议保持原入口。`readiness` 明确只表示定义、绑定和依赖事实，分别显示调用时权限、目标观察和执行证据的边界。

MCP 复用 `mcp.servers.list`、`mcp.tools.list`、`mcp.tool.call`：服务查询可按 app_id 和 offset 分页；工具查询使用远端 next_cursor；调用保存完整、已脱敏的原始结果文件。远程协议支持 stdio 与 Streamable HTTP 的 JSON/SSE 响应，配置是唯一服务器来源，不允许模型提交 spawn 命令或临时 URL。MCP 返回的成功仍只是服务报告，任务需要目标回读和裁判。

连接说明见 [MCP 环境与连接](MCP_CONNECTIONS.md)。缺软件、账号、许可、接口或真实环境，只阻断对应能力。HTTP 服务需要其实际 MCP 接口；普通厂商 REST 地址不能冒充 MCP 地址。

`browser.chrome.goto/open/extract_*` 的静态行为明确标记；截图和打印改为真实 Chromium。`browser.chrome.click` 在新页面点击一次并读取结果；操作后观察失败为未知副作用。`sqlite.query.run` 合并为显式 `sqlite.query` 别名；默认只读由 SQLite 连接及 authorizer 实际约束，包含 WITH 写语句和 PRAGMA 反例。

## 验收及证据

验收单位为能力需求 × 平台环境 × 输入边界 × 副作用故障。别名验证等价后共享实现证据。正确结果无谓返工和错误结果被放行都需记录。

保留既有 V01–V24 反例分类，覆盖未实现、单位/类型、账号隔离、缺依赖、分页、截断、仅生成脚本、异步未完成、超时已生效、部分完成、并发编辑、崩溃、迟到响应、会话失效、版本变更、错误内容、缺模态观察、批准后修改、无回执声明、提示注入、重复空转、未执行修复、重复支持及用户反馈变化。以相关实际覆盖退出，不按固定配额填数。

文件、浏览器、远端和多模态分别提供适当内容观察。接口返回值、格式正确、元数据或裁判文字都不能单独证明目标效果。开发测试的已知真值不成为产品关键词质量门。

原始要求、源码/字典摘要、输入、模型、组合、回执、产物版本、修复历史和裁决共同绑定候选。SOURCE、CONTROLLED_TEST、LOCAL_REAL、MODEL_LIVE、EXTERNAL_LIVE、HISTORICAL 分开记录。所有失败保留。

复验入口见 [普通产品入口驱动](../../scripts/ontology-smoke/README.md)，反例覆盖见 [验收矩阵](VALIDATION_MATRIX.md)。旧前端固定 Skill 场景及其回复文本分类器仅保留历史兼容，不作为本方案的完成证据；本批核对真实账本、产物及有效对抗裁决。

## 当前范围与持续实施

[覆盖清单](capability-coverage.json)由 `scripts/build-ontology-coverage.py` 生成，是文档投影。清单完整不代表所有原子粒度已经审定，也不代表所有外部账号接通。每一项未验证能力继续显示所需证据；不会自动把 implemented 或配置文件存在升级为可交付。

接口版本改变后，旧组合不得静默重解释；从原目标与已完成事实生成剩余步骤。经验保留原版本和作用域，失败/撤销影响召回，主动探究只关闭有实际新观察的缺口。99% 缓存命中率不是退出条件；完整成本包含执行、裁判、辅助与失败调用，未知用量单列。

每批退出需要：范围明确、真实执行与观察、适用反例、有效当前裁决、必需候选检查、未支持清单及回退。部分批次可以交付，整体未覆盖项不得关闭。
