二、关键设计决定
----------------------------------------------------------------------
D1 哈希诚实性（吸收审核三.1）
    所有 *_sha256 为无密钥内容哈希：证明内部一致性与可复算，
    不证明生产者身份。docstring 与 M0 审计口径一致。

D2 ID 不进自身预映像（冒烟测试抓出的死锁）
    registry_snapshot_id / verification_record_id 由各自 sha256 派生，
    computed_*_sha256() 排除派生 ID 字段。快照哈希同时排除
    captured_at_ms：同一描述符集合在任何时刻 pin 出同一身份。

D3 快照身份时间不变性
    VerifierRegistry.snapshot() 对相同描述符集合产出恒定
    snapshot_sha256/registry_snapshot_id，recorder 据此 pin。

D4 NOT_APPLICABLE 显式化（吸收审核 M1 契约要求）
    VerificationStatus = PASS/FAIL/INCONCLUSIVE/ERROR/NOT_APPLICABLE。
    「不该调用」用 NOT_APPLICABLE，禁止伪装 INCONCLUSIVE。
    约束：PASS 与 NOT_APPLICABLE 不得携带 reason_codes。

D5 evaluation_phase 必填（吸收 M0 发现2）
    POST_EXECUTION / PRE_DELIVERY / DELIVERY_FINALIZATION /
    ASYNC_OBSERVATION。只描述证据产生节点，无阻断权。
    M4 接线时 desktop 与渠道按各自实际相位标注。

D6 enforcement 双层约束
    契约层：RecordedEnforcement = Literal["RECORD"]（M1 类型级禁止
    ALERT/BLOCK）；DB 层 CHECK 保留全三值（未来里程碑免迁移重建）；
    recorder 层：再校验 enforcement == "RECORD"。审核清单第 14 项
    （所有记录只能是 RECORD）由 test_p19_m1_store 断言 DB 实际行。

D7 休眠 oracle 描述符
    三个 verifier 以 descriptor 形态注册（layer=L0、deterministic、
    block_capable=True 但 default_enforcement=RECORD、无 handler）。
    M2/M3 实现真实 inspector 时版本推进、快照身份随之改变。

D8 上游未决定（吸收审核对发现1 的裁定）
    本阶段不实现 VerificationPlanCompiler、不接线 CommitmentCompiler、
    不从 V3 正则或 Office 预检编译 predicate。predicate_type 仅以
    allowlist 形态存在，供描述符声明与 recorder 校验。

D9 请求绑定复用
    put_verification_record 走 _assert_request_binding_locked
    （store.py:3392 既有函数）：request 必须存在、run/generation 必须
    与 request_generation 一致——跨 run/跨代写入直接 StoreConflictError。

D10 基线链推进遵循仓库惯例
    P19 常量新增、REVIEWED 指针前移、P18→P17 推导前先做
    P19→P18 推导断言（剥离三个新模型 = P18 原包，逐字节验证）。
