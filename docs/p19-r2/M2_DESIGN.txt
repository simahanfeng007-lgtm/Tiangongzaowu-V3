二、关键设计决定
----------------------------------------------------------------------
D1 机械迁移纪律
    函数体逐字复制（含 except Exception: continue 的既有静默行为
    与 max_row 含表头的既有语义），未顺手改正则/阈值/文案。原测试
    test_office_content_gate.py 5 项不改一字通过；re-export 与迁移
    函数为同一对象（identity 断言）。

D2 双层彻底分权
    旧预检：user_message 正则 → host path 读取 → 中文 gap 列表，
    仅 simple_chain 同轮纠错，不得生成权威 predicate（模块级
    导入边界断言锁定：不 import contracts.verification /
    total_gateway）。
    新 Oracle：只接受显式 ArtifactPredicate（predicate_id/type/
    params）+ 已绑定的 ArtifactManifest；从 user_message 推导需求
    的路径在本层不存在。

D3 权威链复用（不重造）
    Oracle 经 VerifiedArtifactContentSource（manifest PASSED+QC
    evidence+manifest hash → FactLedger QC facts 复核 → object
    reference 六元组绑定 → immutable bytes 读回复算 sha256/size）
    取得字节，绝不打开本地 path。权威链任何失败 = ERROR（含
    ObjectStoreCorruption 等 store 自身异常——广捕获是有意的：
    权威阶段任何异常都不得逃逸或静默放行）。

D4 状态语义严格化
    PASS/FAIL 只来自确定性证据；解析不可靠（ContentUnparseable、
    不支持格式、超输入上限、无文本可量的 pptx）→ INCONCLUSIVE；
    权威/读回/运行时异常 → ERROR；谓词与 subject 天生不匹配 →
    NOT_APPLICABLE（M1 契约规定不带 reason codes）。
    「解析失败当空内容判 FAIL」被结构性禁止。

D5 能力诚实面（吸收审核附加要求）
    已实现并测试：artifact.nonempty / artifact.min_visible_text_chars
    / xlsx.required_columns / xlsx.min_data_rows（表头不计入——与
    旧预检的 max_row 语义在此层修正）/ text.required_markers /
    pptx.min_nonempty_slides（纯图片 deck 无文本可量 → INCONCLUSIVE
    而非 FAIL）。
    明确未实现（INCONCLUSIVE + predicate_not_implemented）：
    csv.required_columns——gate 无 csv 格式策略（.csv 不在 text
    扩展白名单），权威链上根本到不了 csv manifest；其余 M1 描述符
    声明的谓词同此处理。宁可能力少，不假装验证。

D6 xlsx 数据行语义修正仅限 Oracle 层
    Oracle 的 data_row_count = 表头后的非空行；旧预检保持 max_row
    含表头（D1 纪律）。两层结论允许不同——分权后各司其职，
    M2-07 的 BLOCK 切换条件满足前无阻断影响。

D7 记录身份与持久化
    产出的 VerificationRecord 满足 M1.1 身份绑定（has_valid_identity
    断言）；经 Recorder/Store 留证时 enforcement 恒 RECORD，且零
    CompletionDecision/aggregate_state/outbox 变化（测试逐表断言）。
