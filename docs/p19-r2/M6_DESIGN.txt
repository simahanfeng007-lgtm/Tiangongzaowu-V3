P19-R2 M6 — Verification Plane 1.0 Final Freeze 设计说明
基线：a94035f221d8769dcf4d5bcd1e7fa2827aa9623a

# 0. 目的

M6 不开发新的 Verification/Repair 能力。M0–M5 已交付完整闭环：
Execution → Reality Evidence → Verification → FailureEvidence →
Deterministic Repair Policy → RepairDirective → Single-flight existing
Runtime → New Reality → Subject Successor → Same Predicate
Re-verification → CompletionGate。

M6 的任务是证明该系统在正常/异常/崩溃/并发/漂移/跨平台/长程
条件下保持相同 authority semantics，并冻结为 Verification
Plane 1.0。

# 1. 六个工作流

A. Golden Trace
   tests/golden/p19_r2/test_golden_trace.py（G01–G15）
   - 每个 canonical scenario 跑真实 Store/Gate/executor/policy/
     repair loop，收集全部权威对象为 machine-readable trace
   - 归一化：wall clock/volatile id 永不入比较；trust-boundary
     hash 以 intern（同值同占位）保留拓扑；completion decision 的
     states 数组降维为 QC 状态多重集（其拓扑已由 records/
     successors 锁定）；非时序对象数组按去占位结构排序
   - G14（双 worker race）为时序非确定场景，golden 契约为不变量
     集：runtime execution count == 1、单 attempt、单 successor、
     单 SUCCEEDED binding
   - compare-only：CI 永不重写基线；显式维护命令 UPDATE_GOLDEN=1

B. Golden CI + Architecture Guards
   .github/workflows/p19-r2-golden-gate.yml（ubuntu+windows）
   tests/golden/p19_r2/test_freeze_and_guards.py
   - AST 结构扫描（非字符串扫）：CompletionGate/GatewayStateStore/
     BackendClient/VerificationRepairCoordinator/
     VerificationPlanExecutor/ArtifactGate/EffectStateOracle/
     RepositoryStateOracle 类定义各恰好 1 处；STORE_SCHEMA_VERSION
     唯一且无第二 GATEWAY* schema 权威；CompletionDecision 构造仅
     存在于 completion_gate.py；无独立 repair daemon 入口

C. Calibration & Drift
   tests/golden/p19_r2/test_calibration_and_stability.py
   - Artifact corpus：docx/xlsx/text 正负样本（空文件在 object
     store 权威层即被拒——正确的 fail-closed）
   - Effect corpus：六 ledger 状态下 terminal_succeeded 判定
     （AMBIGUOUS 永不 PASS）
   - Repository corpus：真实 git 仓库 + 独立 sensor（path changed/
     unchanged/wrong path）
   - 验收：False PASS == 0（release BLOCKER）；False FAIL == 0 或
     已分类说明
   - Drift：VERIFICATION_PLANE_FINGERPRINT.json 锁 registry/
     verifiers/policy config/gate sha/store schema/authority map/
     golden corpus；不匹配即 UNEXPECTED_DRIFT → CI FAIL；显式
     升级须人工更新指纹（UPDATE_FINGERPRINT=1）并同步声明

D. Fault Injection
   tests/golden/p19_r2/test_fault_matrix.py（F01–F16）
   - 在权威流水线的精确点截断（真实 Store 状态、绝不 mock 核心权威）
   - 恢复语义：RESERVED 未跨界→同 directive 继续；跨 SIDE_EFFECT_
     STARTED→零重放 RECONCILE；SUCCEEDED→仅 Store 恢复零 Runtime；
     PASS 后 Gate 未跑→不得 repair
   - 硬指标（全部为 0）：False Completion / Duplicate Side Effect /
     AMBIGUOUS Replay / Stale PASS Reuse / Completion Bypass

E. Stability / Long-Horizon
   - 150-turn 连续验证链 + 每 30 turn Store 重开（continuity/
     supersession/无陈旧完成）
   - successor 链：真实修复推进且受预算约束（不 fork、不 cycle）
   - 并发认证：双 worker 同 FAIL/同 directive/successor 幂等竞争
   - Performance envelope：p50/p95/p99 记录于
     PERFORMANCE_ENVELOPE.json；只防灾难性退化（p99 < 5s）

F. Architecture Freeze
   - VERIFICATION_PLANE_VERSION = "1.0"（唯一机器可读版本源：
     src/total_gateway/verification_plane.py）
   - VERIFICATION_PLANE_FREEZE.json 锁 authority surface hashes；
     任何 completion/repair/plan/successor/fencing/binding/schema
     语义文件变化 → VERIFICATION_PLANE_FREEZE_CHANGED → CI FAIL，
     要求显式版本升级（UPDATE_FREEZE=1 重生成 + 版本声明）
   - docs/p19-r2/AUTHORITY_MAP.txt 终版权威链

# 2. 已知边界（诚实声明）

1. repository「完全无变更」窗口：wall-clock 观测契约下零 delta
   的 POST 与 PRE 共享内容身份，unchanged-FAIL 语义由「非空 delta
   但不含 required path」表达（calibration 注记）。
2. 长 revision 链受策略预算约束（per-entry 2 次修复、successor
   depth 4）——「不 fork 不 cycle」在预算可达范围内验证。
3. Channel 侧 artifact 修复桥注入点就绪但装配层未接（M5 冻结的
   安全保守行为：delivery 后零自动执行、零重发）。

# 3. Release hard thresholds（§20）

False Completion = 0；False PASS = 0；Duplicate Side Effect = 0；
AMBIGUOUS Replay = 0；Completion Authority Bypass = 0；Stale
Authority Acceptance = 0；Single-flight Violation = 0；Golden
Critical Case Failure = 0。任何一项非 0 不得封板。

# 4. 缺陷处理纪律（§29）

Golden/fault 发现 M0–M5 缺陷时：指明被破坏的 invariant、只修现有
authority、不建第二系统、补 regression、Golden 更新仅限获批语义
变化、全部回归重跑、不开 M6.x。
