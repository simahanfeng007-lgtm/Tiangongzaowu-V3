P19-R2 VERIFICATION PLANE 1.6 — P8 SOURCE EVOLUTION BOUNDARY REVISION
======================================================================

Scope and baseline
----------------------------------------------------------------------

This is the explicit P8 revision of the existing Verification Plane, based on
P7D.2 main 9a3344de9fe468fa845d2ff501166484439b8ec4. It is not a second plane,
registry, runtime, store or publication authority. P8 acceptance is tracked in
docs/capability-composition/P8_P17_PROGRESS.md and is not implied by this version.

The single machine-readable version source remains:

    src/total_gateway/verification_plane.py

Changes covered by this revision
----------------------------------------------------------------------

1. Existing fact_kernel.compile_manifest gains an explicit Gateway-format
   projection. Runtime and published source-hash domains remain distinct;
   both are derived from the same compiled capability rows. The projection
   does not replace the published Manifest or import new runtime source.
2. Immutable Git candidate observation and native-blob materialization bind
   source review to exact base/candidate commits. Candidate data cannot amend
   its own source-ownership policy, execute hooks/filters, or impersonate an
   authoritative/generated/frozen source owner.
3. Manifest differentials reuse existing Action Registry and schema compilers.
   Direct and inherited alias changes, risk downgrades and new A0 candidates
   are visible review data, never permission or Source publication approvals.
4. The existing sandbox has a stricter build-only requirement which rejects
   unavailable OS containment before launch. Explicit compatibility fallback
   cannot override it. Isolated build reports retain their input identities,
   compiler bindings and observed results without claiming review, publication,
   evidence-contract evaluation or production task completion.
5. Strict source-build paths use the extended Windows namespace for deep
   private inputs and cleanup without changing the host LongPathsEnabled
   setting or weakening filesystem/OS isolation.
6. Isolated builds bind a conservative, byte-hashed closure of the existing
   editable/frozen source roots and dependency inputs. Generated mirrors and
   the generated Capability Manifest do not participate in their own input
   revision. Parent-observed input bytes must match the child build report.
   The existing compiler's Gateway projection includes source_inputs_sha256;
   its whole-document authority hash changes even for handler-only edits.
   This does not change permission semantics or approve publication.
7. Manifest differential review is Gateway-owned. World Understanding does
   not import the Gateway to recompile permissions. The existing layer guard
   remains unchanged; the P8 review module is moved, not re-exported by World.
8. Git candidate observation/materialization and source-input evidence also
   belong to the Gateway's offline source lifecycle, not World Understanding.
   World retains its existing no-process/no-runtime-import invariant. The two
   P8 modules move with their freeze coverage; no World forwarding module or
   source-ownership policy exception is introduced.
9. The existing production Manifest loader accepts the original seven-field
   release or its explicit P8 source_inputs_sha256 extension. If present, that
   field must be lowercase SHA-256 text. Unknown roots remain forbidden. The
   complete file digest is verified once before both model and registry/schema
   projections; the extension cannot bypass a release pin or approve changes.
   Loaded-object isolation tests are not proof of running-task version locks.
10. The trusted source-build parent derives source-bound Tool World descriptors
    from its observed input closure and verified ACTIONS entry-module binding.
    It reuses the existing Action Registry/schema and P2 Tool World compilers;
    models do not supply source revisions. Revision identity conservatively
    covers transitive input bytes. Implementation references are module-level
    entry references, not an inferred per-handler dependency graph. Input
    records reject malformed types, paths, sizes and ownership digest drift.
    This output is build-review data, never automatic World ingestion or Source
    publication, and it does not alter the existing A0 admission ceiling.
11. The existing manifest compiler rejects explicit malformed Action risk,
    effect, implemented, alias and dynamic-route identities instead of coercing
    them or silently applying defaults. In particular, a misspelled execute
    effect cannot become read, and the string "false" cannot declare an Action
    implemented. Legacy omitted-field defaults are unchanged, not approved risk
    classifications; the full source-versus-published risk audit remains open.
12. Real Gateway-to-Omni consumer tests exposed a P7D.2 compatibility gap:
    the consumer rejected the existing signed continuation/attempt/predecessor
    fields as unknown. It now validates their complete existing contract shape
    before signature/nonce acceptance. Gateway/Store still own eligibility,
    predecessor CAS and dispatch; no continuation is authorized by data alone.
    Runtime binding comparison uses exact canonical JSON (bool is not int).
    The unchanged A0 ceiling, signature, expiry and replay rejection remain
    mandatory. The Omni consumer source is added to this plane's freeze surface.
13. Existing release generation hashes observed file bytes instead of trusting
    persistent size/mtime digest caches. It does not read, rewrite or delete
    legacy cache files. The existing gateway-source tree now includes all
    editable/frozen roots from validated Source Authority, plus its policy and
    dependency lock. The four-tree release contract and its hash domain remain
    unchanged. Installed generated files inside these roots are also release
    inputs; this release hash does not feed back into Capability compilation.
    No new publication authority or running-task lock is claimed. The release
    generator is added to the explicit authority freeze surface.
14. An explicit embedded-backend source root selects only that installation;
    missing/unsafe roots cannot fall back to checkout, environment or frozen
    discovery. Foreign cached v3/tiangong_kernel origins and namespace search
    paths fail before candidate imports or sys.path mutation. The existing
    process-owner guard stays intact: no module deletion, hot reload or second
    Runtime is introduced. Unspecified-root discovery is unchanged. This binds
    backend startup selection, not every shared module or a live Run's complete
    byte closure; immutable installation and running-source acceptance remain
    required. The embedded-backend source joins the explicit freeze surface.
15. The existing isolated build command can retain a content-bound source ZIP
    after its private snapshot is removed. The compiled Gateway Manifest is
    materialized only inside that private snapshot; installed trusted tooling
    invokes the official mirror generator with an explicit workspace argument.
    Compiler inputs must remain byte-identical across generation. The package
    includes a source-file inventory, exact build report, Manifest and mirrors.
    Verification checks the whole-file pin, portable paths, bounded sizes,
    index/file/report/input/Manifest consistency, and rejects executable-link
    entries without extracting or importing any candidate code. Packages never
    overwrite prior versions and may_publish/may_authorize/may_execute remain
    false. A valid bundle is not Git provenance, review approval, an activation
    pointer or proof of a running-source lock. The packager and existing official
    mirror generator join the same explicit authority freeze surface.

Unchanged authority and admission
----------------------------------------------------------------------

The unique Gateway, Runtime, WorldState, Memory SSoT, Action Registry,
Policy/Ticket/Grant, Effect/Fact, P19 and CompletionGate remain unchanged in
ownership. Gateway Store schema remains 33. No verifier PASS/FAIL/INCONCLUSIVE
rule, Repair Policy, completion rule, or A0-only composition admission rule is
relaxed. A1+, writes, external sends, shell/Python actions and destructive
runtime operations are not enabled by the offline source-build tooling.

Freeze procedure
----------------------------------------------------------------------

Retain every 1.5 authority surface entry and add the source candidate/inputs/review,
trusted source topology validator, sandbox, and installed build/review scripts.
Refresh docs/p19-r2/m6/VERIFICATION_PLANE_FREEZE.json only through the existing
UPDATE_FREEZE=1 generator after inspecting changes. Then rerun the guard with
UPDATE_FREEZE absent and run the full required gates against the final head.
The Golden corpus, oracle semantics and drift fingerprint are not rewritten
merely to obtain a passing test. No phase is closed until its real acceptance
requirements and exact-head evidence are complete.
