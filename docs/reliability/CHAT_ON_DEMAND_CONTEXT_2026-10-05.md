# 无字典对话与按需上下文 · 2026-10-05

基线：`origin/main` 的 `0a29f25c8ea629c4ef529a752cc4b655865452b6`。工作分支：`codex/chat-on-demand-context`。本次为本地源码优化，未推送、合并或更新安装版。

用户要求：未使用字典时不进行质检，并借鉴 Codex 的上下文加载方式。

## 成因与依据

此前普通文字回复也进入 `CompletionSession`，由第二次模型调用判断是否完成。同时，首次请求附带完整动作名称目录、重复的 Soul/ContextEnvelope JSON，以及身体上下文和模型刷新阶段重复加载的世界状态。实际基线“你好”的主调用为 14,314 输入 tokens，加质检 1,278，合计 15,592。

截图中的 172 秒没有对应请求日志，不能据此次实测确认其全部耗时来源。本次对照使用现有配置 `deepseek-chat`，服务端返回身份 `deepseek-flash`，不是原截图请求的复现。

参考的是 Codex 官方公开说明，未宣称核验 Codex 私有实现：[Skills 的渐进式加载](https://learn.chatgpt.com/docs/build-skills)先提供索引、选中后读取全文；[Prompt Caching 201](https://developers.openai.com/cookbook/examples/prompt_caching_201)说明稳定系统/工具前缀与追加消息的结构。

## 修改方案

- 用本轮实际解析到的字典调用记录 `dictionary_used`；无调用的有效文字回复以 `chat_reply / model_response` 结束，跳过模型质检，不预留质检时间。未依据“你好”等关键词硬编码意图分类。
- 一旦出现字典调用，本轮保持 `adversarial_agent` 完成判定，包括发现/查询动作及失败调用。恢复检查点保守沿用审核路径，不能把已有副作用改标成聊天。错误、空回复、取消仍失败或停止。
- 首轮只发送能力分类、调用协议和 `system.capabilities` / `system.action_schema` 查询入口。详细能力按需读取，字典定义、参数校验和权限门控保持原有权威来源。
- Soul 提升到系统提示后，消费其宿主传输副本；ContextEnvelope 保留各项语义渲染，取消重复 JSON。具有工作区路径的学习资料只发送名称、简述和精确路径，无可读取路径的旧资料仍保留内联定义。
- 普通用户轮次不预装世界状态；发生字典调用后刷新。显式受控规划模式仍在第一轮获得世界状态。已有原生调用/结果配对与追加上下文机制继续保留。
- 普通聊天不能凭模型文本导出“已生成文件”。聊天进度事件正确标记 `done / chat`，不会显示为未完成。
- 验证面升为 `1.72`，通过官方冻结更新流程重建清单；生成镜像通过 `sync-generated-sources.py` 同步。
