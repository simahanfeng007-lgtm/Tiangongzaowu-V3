# 工具调用简写兼容与有界纠错 · 2026-10-05

本次在 `codex/chat-on-demand-context` 上修复，接续 PR #119 的无字典聊天优化。字典版本为 `2026.10.05.1`，验证面为 `1.73`，Store 仍为 v33。

## 病因与依据

模型可能返回合法 JSON 的原生 `omni_body(action,target,args)`。原传输层能解析，但编排器只允许三项发现动作使用该格式，其他任务必须提交 `composition`。模型重复返回相同格式时，编排器只反馈错误，直到通用无进展保护触发。拒绝发生在执行入口之前，因此“执行 0 次”不代表模型没有尝试调用。

当前基线的公开 schema 已把直接 action 限定为三项发现动作。因此截图中“schema 明确允许任务直调”的描述不能直接归因于当前版本；未获得原 Strata IQ2_XS 运行版本与原始日志。离线强制模型反复提交简写可重现 11 次模型调用、10 次组合拒绝、0 次执行。

扩大检查发现：多调用转组合必须维持原生 call/result 一一对应；JSON/XML 文本解析会扫描参数里的调用文本，XML 分隔符可截断参数，超过 8 个独立 JSON 对象被静默截断；畸形调用纠错后可能落入无字典聊天路径。

## 修改方案

- 统一 schema、提示与编排入口。有效简写原样包装为任务局部 Tool/Skill，整批通过原有编译、Gateway 登记、参数校验、权限和 Effect 门控之后才执行。没有猜测参数、追加动作或开放裸执行入口。
- 多条简写按原顺序串行执行；保留原模型调用 ID，每个原调用得到一个对应结果。任一步失败，未运行步骤返回明确的 `not_executed`，不伪造成功回执。
- 混合 composition 与简写、未知或禁用动作、非法参数、越界路径、伪造权限字段继续拒绝。登记前校验整批动作，后续动作非法时不会先写出前面的文件。
- 同一无执行进展窗口内，相同非法调用第二次出现即停止；不同错误最多三次。反馈包含具体错误、字段差异和剩余纠错次数。纠错轮连接失败也进入正常失败收尾。
- 原生、JSON、XML 入口保留参数类型和内容；完整 JSON 参数区不再作为工具调用文本扫描。保护 XML 参数中的分隔符与字面实体，保留有意重复的调用，不静默截断长列表；超上限由整批登记入口拒绝。
- 单调用入口复用同一解析器；混用 JSON 与不同 XML 写法时仍按原文顺序处理。无原生绑定的文本/XML 调用通过显式上下文传回结果及错误，避免模型看不到纠错反馈；原生历史只接收绑定数量匹配的调用与回执。
- 解析失败的调用也标记为已尝试字典；连续畸形格式不再作为聊天成功。新增调用尝试数、组合拒绝数及进度事件，执行轮次仍使用现有计数。

PR #119 上一候选的 CI 失败也已处理：同步遗漏的验证面断言；三个模型故障用例显式关闭共享夹具自动插入的发现调用，恢复各自首轮/续答测试意图；按实际源码重建 ontology coverage 与动态调用索引。动态审查注解只重定位原已审查且内容不变的行，131 项均仍有对应记录。未删除失败用例或降低权限断言。

## 修改结果

最终专项 **301 passed / 0 failed**，涵盖三种原生协议、JSON/XML、真实 Gateway 登记及文件动作、失败后停止、批量参数拒绝、原生历史、聊天跳过质检、模型故障、解析纠错、原 CI 失败用例与全部 P19-R2 golden。冻结通过显式 `UPDATE_FREEZE=1` 更新后，以普通模式复验通过。Source Authority、生成镜像、字典发布视图、动态索引与 ontology coverage 检查通过。
