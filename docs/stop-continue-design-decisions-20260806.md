# 停止 / 续接 / 卡死判定 — 设计决策记录

日期：2026-08-06
状态：1、2 已确认（待实现）；3、4 已定稿，总设计计划见 `docs/stop-continue-total-design-plan-20260806.md`

## 背景

对照 Claude Code 与 Codex（openai/codex）的停止/续跑设计后，确认以下原则：

- 续跑/停止由框架层（hook、状态机、事件）决定，不让“正在干活的主模型”自证没卡。
- 卡死判定不能只依赖单工具重复；用进展指纹、状态回环、意图语义重复做多信号判断（已实现）。
- 强制停止要有原因，且走显式终态；普通未完成由大模型判断是否可换方式继续（已实现）。

## 1. 普通“继续决策回合”连续次数上限 = 9（已确认，待实现）

- 现状：普通未完成进入“继续决策回合”，由大模型自行判断能否换方式继续；返回工具调用就继续，纯文本就自然收尾。
- 问题：模型可能每轮都判断“可以继续”但实际原地打转，缺少框架层硬上限。
- 方案：连续继续决策达到 **9 次**（`MAX_CONSECUTIVE_CONTINUE_DECISIONS = 9`）时，框架停止继续回合，转 `force_stopped` 收尾，并附带原因“连续 9 次判断可继续但未取得足够进展”。
- 计数规则：只统计连续继续决策；出现纯文本收尾、用户介入或 `force_stopped` 时计数清零。
- 参照：Claude Code Stop hook 连续 8 次 block 后强制结束；按用户要求取 9。

## 2. 终局失败做成显式状态（已确认，待实现）

- 现状：模型调用失败（API 错误、重试耗尽、上下文/工具错误等）若被当作普通未完成处理，会进入继续决策回合反复重试。
- 方案：
  - 终局性错误（非重试错误，或重试耗尽）→ 显式 `force_stopped`，附停止原因，不进入普通继续决策回合。
  - 预算/用量类错误单独处理：预算用尽走预算收尾轮（类比 Codex 的 `usage_limited` / `budget_limited` 状态），不是普通失败。
- 参照：Codex PR #26690 —— 终局性 turn 错误会 block 当前 goal，不再自动续跑；usage-limit 单独过渡。

## 3. 预算/目标状态持久化（讨论中，初稿）

### 现象

- 切换/保存新的 VRM 后，页面一刷新又回到初始 VRM。
- 简单链任务跑到一半，前端刷新/重启后任务状态、已用轮次、剩余预算、续租记录丢失。
- 续租成功后，界面或监控看到的还是旧预算。

### 方案方向

把“当前运行状态”从内存搬到磁盘（后端小数据库或状态文件），前端刷新只重读、不重建：

- 状态对象包含：当前 VRM id、简单链是否在跑、已用/剩余轮次、墙钟与单工具时间、`force_stopped` 原因、当前状态（active / paused / interrupted / budget_limited / force_stopped / complete）。续租机制确认不加入，未来若加按“新状态必须新增事件”规则扩展。
- 刷新或重启后，前端向后端要状态，按持久化状态恢复，而不是回到初始默认。
- 每次预算变更/续租/状态迁移都原子写入，旧状态更新带版本保护，防止覆盖新状态。
- 参照：Codex `thread_goals`（SQLite 持久化 goal_id、objective、status、token/time 记账，goal_id 防旧更新覆盖）。

### 边界

- 只持久化“运行态”，不把完整聊天历史迁移进来；聊天历史沿用现有落盘机制。

## 4. 失败走事件，不走对话文本（讨论中，初稿）

### 现象

- 强制停止时系统回复混入聊天框，用户要求聊天框内看不到系统回复。
- 之前用“自然回复是否重复”判断模型是否卡住，容易误伤且依赖文本内容。

### 方案方向

把信息分成两个通道：

- **事件通道（机器可读）**：`turn.failed`、`force_stopped`、`budget_limited`、`continue_decision` 等结构化事件，写入工作日志/事件流，供前端状态栏、网关 watchdog、外部监控消费；不显示为聊天气泡。
- **对话通道（自然语言）**：只有用户消息和大模型的自然回复。模型收尾用自然语言，但原因通过系统侧载荷注入，不出现在聊天文本。

卡死监控改为事件 + 指纹判定，聊天文本只用于展示；“自然回复重复”降级为可选信号，不再作为主判据。

参照：Codex `codex exec --json` 的 JSONL 事件流（turn.completed / turn.failed）；Claude Code 的 StopFailure 事件只通知不决策。
