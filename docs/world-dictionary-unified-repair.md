## 三轮追查

| 轮次 | 发现及原因 | 统一处理 |
|---|---|---|
| 1：实际入口 | 普通动态组合绕过静态能力投影；直接接旧入口会制造 Git/运行时两个 frame，导致上下文选择失败 | 当前工作区 frame 内投影已发布的字典定义；首轮自动观察，显式选择本次 Life、principal、workspace；不安装业务 Skill |
| 1：可读性 | 基础上下文主要是 ID；文件写入事实没有进入实体/关系图 | 对当前快照内可验证正文生成描述；只有权威写证据能产生 File / WRITES，删除会退役实体 |
| 2：状态连续性 | 限频/失败返回空列表会清掉旧假设；只持久化引用，重启没有正文 | 保存有哈希约束的假设正文；延期保留，依据变化标记 stale；新推断替代旧推断；旧引用不伪造正文 |
| 2：任务连续性 | 系统提示只在任务开始生成 | 每次字典模型调用和最终收尾前替换唯一 World slot；更新失败移除旧 slot |
| 2：记忆语义 | 认可组合存在于 MemoryCoordinator，但世界经验入口未接；直接标为 STABLE 会伪造认知等级 | 从同一记忆权威只读投影 USER_APPROVED / QUARANTINED 摘要，核对当前运行身份；原完整程序召回仍负责详细做法，不建立第二份经验库 |
| 2：接口一致性 | 编译器允许 experience_refs，模型看到的 host schema 不允许 | 更新字典协议、发布版本及生成视图校验；已有原子动作定义不变 |
| 3：并发与故障 | 语义网络调用占着全局世界锁，慢结果还可能晚于新事实到达 | 先提交确定性事实，再在锁外推断；完成后严格比较状态，过时分析丢弃，绝不重放旧事实 |
| 3：预算与体积 | 环境初始化可提前耗尽语义预算；全目录投影一次快照达到约 59 MB | 初始化不调用语义模型；实际结果/文件/代码/用户输入才进入预算；每份动态快照最多 32 个能力引用，不复制业务流程或目录关系全集 |
| 3：可观测性 | 原生观察、能力投影或后置回调异常容易静默降级 | 有界原因码/异常类型日志，保留任务结果，避免日志输出原始载荷和密钥 |
| 3：真实路径 | Windows 文件路径不符合 OpaqueId 语法；工具身份和能力定义同名可能使关系解析不唯一 | 路径转为确定性不透明引用，正文保留原路径；Tool/File 使用来源身份别名解析 |
| 实测回查：协议 | schema 允许 discovery 和 composition 混用，HTTP 转换丢弃根约束；字段错误不带位置 | 增加互斥分支并完整传递 schema；返回缺失/多余字段与节点路径，保持原验证门槛 |
| 实测回查：收尾 | 普通文件实体被仓库证据 reader 误判为 Git 仓库，Life 拒绝提交，产生“模型完成、Gateway 失败” | 仅真实 Git frame 提供仓库证据；Gateway 在加入可选证据前按 Life 契约验证，拒绝无效附件但继续正常提交 |
| 实测回查：输入边界 | 合法 composition 被二次编码为字符串时反复重试；原生参数转换成展示文本后又被正则扫描，代码/HTML 中的调用标签可能被截断或误认 | 在原有边界只还原完整、无重复键的 JSON 对象；原生调用直接读取结构化参数，不扫描代码正文；编译、权限和执行证据校验保持有效 |
| 实测回查：绑定与诊断 | 仅注入回调的临时调度器会清空已有 HTTP 绑定；仅 INFO 日志不能确认生产链是否运行 | 无 HTTP 所有权的实例不清除有效绑定；沿既有诊断通道记录请求 ID、状态、原因、模型引用、耗时和假设数量，不写入原文或密钥 |
| 实测回查：文件导入 | file.read 把“写入使用标准 UTF-8”的限制也强加给导入文件，拒绝常见带 BOM 的 CSV | 复用现有 Unicode 解码器，按明确的 UTF-8/16/32 BOM 严格解码，返回实际编码；不改动源文件，证据仍校验原始字节，不猜测乱码 |

## 运行流程与边界

普通消息进入原 Gateway 后，当前任务首次模型调用读取已发布字典，为同一运行时世界建立有上限的候选能力引用。LLM 仍然依据用户语义生成本轮 Tool 与 Skill，再由现有组合编译、Gateway 权限与事实执行链执行。世界上下文只提供事实、描述、待验证假设与已认可经验，不创建执行权限。

原子能力依赖、软件安装和权限仍在实际执行时检查；目录中 AVAILABLE 表示存在可路由定义，不保证依赖或外部服务现在可用。超过候选上限的能力仍可通过完整字典查询，模型不是只能使用这 32 个引用。

执行结果先保存，然后才调用当前配置的语义模型。推断有独立期限、总任务期限、每运行次数与限频控制。下一轮模型收到更新后的 World slot。限频与模型错误不丢弃已有假设，但变化的依据会使旧假设失效，不能继续冒充当前事实。正常跨会话仅重建公共定义/环境，并在已授权的同一工作区范围内召回用户认可的组合；不会复制另一会话的私有世界事实。

## 仍须明确记录的能力边界

- **L5 稳定认知的自动晋升仍未形成生产证据闭环。** 代码中有证据门槛和 consolidator，但当前生产任务缺少合格的证据归集/支持撤销接线。不能把单次 LLM 推断或一次用户认可强行标记为 C2/C4。本次保留已有认知引用，不伪造晋升。
- **首次失败、尚未被用户认可的组合，没有完整的跨任务纠错记忆。** 已认可组合的复用失败已有隔离和后续不推荐机制；这不等于每一种新错误都会永久学会修正。按此前用户约定记录这一框架缺口，不增设一个未经设计的第二记忆系统。
- **主动探究只在出现合格知识缺口时触发。** 不为了产生演示记录而人为强制调用；已有去重、回退和恢复机制由回归测试覆盖，普通任务成功不能替代真实主动探究收益验证。
