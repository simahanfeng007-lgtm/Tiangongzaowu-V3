# 网文小说写作

> 只教架构与禁则，不绑文风。模型的笔自己决定怎么写。

---

## 作用域门（先判定，再调用工具）

- 本 Skill 负责一次性的单章/少量章节交付、小说协作资料包、大纲、人物表、线索表、修改记录和连贯性审校。
- 这类任务直接使用 `file.write`（用户指定 Word 时用 `docx.create`）和对应 QC；不得调用 `novel.project.create`，不得自行假设全书字数或章数，也不得为了写一章先补齐整书蓝图。
- 只有用户明确要求新建/续作整书、长期多章自主连载，或者目标目录已经是 `novel.*` 托管项目时，才切换到小说权威系统。未满足这一触发条件时，本 Skill 的轻量交付路径优先于通用小说工具说明。

## 大纲模板

用户要大纲时直接输出，不要反问：

```
# 《书名》大纲

## 一句话梗概
{主角} + {核心冲突} + {独特卖点}

## 核心设定
- 主角：{姓名/身份/性格3特质/目标}
- 金手指：{能力/限制/代价}
- 世界观：{时代/力量体系/核心规则}
- 主要对手：{身份/冲突根源/对手的优势}

## 三幕结构
第一幕（~25%）：日常→激励事件→主角反应→第一幕转折
第二幕（~50%）：升级冲突→中点转折→最低谷
第三幕（~25%）：反攻准备→最终对决→新日常

## 章节细纲
| 章 | 场景 | 情绪目标 | 核心事件 | 章尾钩子 |
|----|------|---------|---------|---------|
```

## 小纲四步法（写细纲用）

1. **分段判断** — 把大纲按剧情节点分段
2. **标注目的和效果** — 每段标注，不展开情节
3. **标注详写/略写** — 明确哪些展开、哪些带过
4. **快速定位** — 让后续写作能快速定位本段目的

---

## 高潮逆推法（AB粗纲）

从高潮反推前面需要的铺垫：
- **A** = 压情绪/铺垫/伏笔
- **B** = 抬情绪/擦边/小收获

流程：确定高潮 → 反推所需铺垫 → ABABAB排列 → 写作时只关注当前AB段。

## 防漂移机制（超长篇）

> 百万字级长篇小说最大敌人：忘了前面的人物状态、伏笔、主线方向。

### 写前强制回读（三读法）

写第 N 章之前，必须依次读三份文件：

```
第一读：大纲/细纲.md → 确认本章在整体结构中的位置
第二读：追踪/角色状态.md + 追踪/伏笔清单.md → 当前状态
第三读：正文/第{N-1}章.md（末尾80行）→ 承接上章结尾
```

### 写后状态更新（5 份追踪文件）

写完第 N 章后，必须更新：

**追踪/角色状态.md**：每个出场角色的位置/情绪/目标/装备/已知信息/关系变化

**追踪/伏笔清单.md**：
```
活跃伏笔：[ ] 第X章埋 → 计划第Y章回收
已回收：  [x] 第N章回收 ✓
危险区：  [!!] >20章未回收，需立即规划或砍掉
```

**追踪/时间线.md**：`第N章 | 日期 | 时间段 | 关键事件 | 出场角色`

**追踪/章节速查.md**：`第N章 | 标题 | 一句话摘要 | 情绪 | 新角色 | 新伏笔 | 回收伏笔`

### 上下文截断策略

AI 写作特有问题：对话历史超过 8 章后前面内容会被挤出。

**不靠记忆，靠文件**：写第 N 章只需 4 个文件：
1. 大纲/细纲.md
2. 追踪/角色状态.md
3. 追踪/伏笔清单.md
4. 正文/第{N-1}章.md

追踪文件的信息必须足够让"完全失忆的 AI"接上。

### 30 章编辑轮

每写完 30 章（约 6-10 万字）：
1. 读追踪/章节速查.md → 回顾整体走向
2. 对照大纲 → 偏差<10%（更新大纲）/ 10-30%（评估）/ >30%（回到 checkpoint 重写）
3. 检查伏笔：该回收的设截止章节，该砍的果断放弃
4. 更新编辑轮记录

### 漂移分级响应

| 级别 | 症状 | 响应 |
|------|------|------|
| 🟢 微漂 | 角色语气略有变化 | 当前章内修正 |
| 🟡 中漂 | 剧情偏离大纲、角色做了不符合人设的决定 | 评估：新方向更好→更新大纲；错了→重写本章 |
| 🔴 重漂 | 连续 3 章偏离大纲、时间线矛盾、伏笔丢失 | 回到最近 checkpoint，重写后续 |
| ⚫ 失控 | 主线模糊、角色面目全非 | 停止写作，逐章对照大纲做剧情审计 |

### 超长篇策略（>200章）

- **分卷管理**：每卷 30-50 章，独立卷纲+角色状态+伏笔
- **季度大审（每 100 章）**：通读章节速查→检查主线/力量体系/配角
- **换地图检查**：明确目的/高潮结尾/离开条件/带走什么

## 卡文对策

1. 回顾本章情绪目标
2. 回到角色动机——角色为什么在这里？想干什么？
3. 引入新信息——新角色/新线索/意外事件打破僵局
4. 跳过去——先写后面场景，回头补
5. 降低标准——先写出来，修订时再打磨

## 禁则：绝对避免的 AI 写作模式

> 以下模式出现即 AI 味。不是规定"应该怎么写"，而是告诉你"这些不能出现"。

### 禁止类一：AI 高频词

以下词语在小说中出现 = AI 签名，**禁止使用**：

不禁 / 仿佛 / 宛如 / 映入眼帘 / 心中暗道 / 沉声道 / 淡淡地说 / 脸色一变 / 嘴角微扬 / 不由自主 / 只见 / 此时此刻 / 目光如炬 / 未来可期 / 前途无量 / 充满希望 / 前所未有 / 可谓 / 意义深远

### 禁止类二：弱化副词堆积

微微 / 淡淡 / 缓缓 / 轻轻 / 稍稍 —— 每千字超过 3 个即 AI 签名。非用不可时才用一个。

### 禁止类三：论文体侵入

以下开头如果出现在小说叙事中 = AI 入侵，**禁止**：

不难看出 / 由此可见 / 事实上 / 综上所述 / 之所以……是因为 / 这意味着

### 禁止类四：解释腔与上帝视角（最难察觉，最像 AI）

**禁止**以下叙事模式：
- 替读者下结论：不说"演得真好"——摆出表演的证据让读者自己判断
- 替角色总结心理：不写"她明白，这一切都是命"——用闪念或身体反应
- 上帝剧透：不用"她不知道的是""殊不知""多年以后""冥冥之中"
- 章尾升华收束：章尾不总结、不定性、不拔高
- 定性比喻：不写"像在宣判一件早已定好的事"——除非是角色此刻强烈主观感受
- 评判性副词：不写"关切得恰到好处""笑得恰如其分"

**核心自检**：每句问——这是"角色在经历"还是"作者在讲解"？凡作者跳出来，删。

### 禁止类五：三连排比癖

AI 喜欢凑成三个显"完整"。三个砍到只剩最有力的一条。

### 禁止类六：书面语连词泛滥

于是乎 / 与此同时 / 从而 / 因而 / 诚然 —— 小说中出现即 AI 味，口语化替代或直接删除。

### 禁止类七：大段纯心理

连续超过 2 段纯心理描写 / 内心独白 / 括号标注内心 → 断开，穿插动作或对话。

## 可用 Action

| action | 用途 |
|--------|------|
| `file.write` | 写大纲/章节/设定，用 `args.content` |
| `file.read` | 读取已有内容 |
| `file.list` | 查看项目文件 |
| `file.mkdir` | 创建目录结构 |
| `docx.create` | 导出 .docx 书稿，`args.sections`（每章一个 section） |
| `web.search` | 查资料 |

## 交付规则

- 每次生成文件后，**必须在回复中输出文件的绝对路径**，格式：`MEDIA:完整路径`
- 不需要等用户说"发给我"——每次写文件后直接把路径给用户
- 用户要 Word 就用 `docx.create` 一步生成，不要先写 md 再转
- 用户要 md 就用 `file.write`，不要同时生成 docx
- **一次只生成用户需要的格式，不要同时生成多个格式的文件**
